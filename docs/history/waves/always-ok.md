# always-ok -- always-OK status functions made void (rule 7)

## Scope
Every agc_status_t function whose returns are all AGC_STATUS_OK
(`make always-ok-report`) becomes void; callers lose their status plumbing;
dispatch regenerated for void jobs/tasks. Then the leadin.c silent skip
(rule 7) + a check_rules pattern, then returns-extra in
tools/prolog_check.py. src/exec/**, src/csm/entry/**, src/sim/** were
excluded while loose-ends ran (wave 1); the lead lifted that mid-run.

## Method
* tools/cocci/always_ok_void.cocci (regenerated per wave from the
  report's names): definition/prototype -> void, `return (AGC_STATUS_OK)`
  -> `return;`, callers' `(void) f()`, `return f()`, `st = f(); if (st !=
  OK) return st;`, `CHECK(f() == OK)`.
* tools/drop_final_return.py: the final `return;` of a void body goes; its
  AGC exit comment (ENDOFJOB, RESUME) joins the previous statement.
* The rest of the call sites (status chains, ternaries, a status kept for
  a later test) by hand from the compiler's "void value not ignored".
* tools/gen_registry.py: a handler declared void in a header is emitted as
  `f(); return (AGC_STATUS_OK);` in src/exec/dispatch.c.
* Prolog RETURNS of each converted function -> `RETURNS: none` (keeping
  any non-status description).

## Findings
* Removing status plumbing surfaced swallowed statuses, now handled:
  steer.c (a BAD_ARG of agc_guid_steering_tgo_csm ignored),
  prelaunch_gyrocompass.c azimuth check (gyro_buf_get status overwritten
  before it was tested), planetary.c (lv read uninitialised when EARTHMX
  failed).
* src/core/ecadr.c agc_erase_read_ecadr has no range guard since the EVA
  deletions (dacba35); callers mask to 15 bits (PIN_WORD, ECADR_MASK,
  EC_ERASABLE check in systems_test), so it holds; noted for EVA.
* The first cocci draft deleted `return;` with a path rule (`... return;
  }`), which also matched EARLY returns (agc_task_t6start lost its TIME6
  wait and its per-BLAST RESUME); caught in review, restored, rule
  replaced by tools/drop_final_return.py (statement-level, libclang).

## Lessons
* A Coccinelle `... return; }` rule is path-based: every return reaches
  the function end, so it deletes early returns too. Delete only the
  statement-level last return (libclang: last child of the body).
* returns-extra must ignore a literal under == / != (`(st == BUSY) ? OK :
  st` filters BUSY out); the assigned-literal heuristic still over-reports
  a status that is consumed before the return (agc_job_standby).
