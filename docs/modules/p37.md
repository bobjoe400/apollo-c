# p37 -- P37 return to earth (Comanche055 P37_P70.agc, pp. 890-933)

## Scope
Comanche only. The whole of P37_P70.agc: the P37 program (displays, conic
search, precision search, targeting for P40/P41) and its subroutines.
XT1LIM was translated by guid-entry; its public wrapper is kept, the body is
re-done with the real index register (see Deviations). The file holds no P70

is not translated anywhere in the tree; a local copy is kept here
(src/csm/burns/return_to_earth/conic.c) until guidance exports it.

## Deviations
- P37W (src/csm/burns/return_to_earth/program.c): the AGC VLOADs RTARG from the push-down list
  (no address), so a V16N45 recycle pops a stale cell; the C keeps the
  targeting vector in rte_erasable_t.rtarg and uses it every time.
- AUGEKUGL (src/csm/burns/return_to_earth/conic.c): the K1/K2 table walk by index
  registers (X1, S1, TIX) is replaced by explicit band selection; the speed
  comparisons are the same DSU chain (21K, +3K, +4K, +400 fps).
- V2T100 (src/csm/burns/return_to_earth/velocity.c): THETA1 - X^2 and THETA2 are
  normalised as TP and then used as DP (the third word only changes the
  last bit of the DDV quotient).
- XT1LIM: re-done with the real X1 left by V2T100 (pl->x1); the guid-entry
  public wrapper agc_return_to_earth_xt1lim keeps its signature (BETA5 B9).
- B29/B27 pairs: P37 refuses a moon-sphere state (alarm 612) so only the
  earth scale is coded.
- Precision loop: bounded by RTE_PREC_MAX_STEPS (400 integrations) in
  addition to the AGC's NN1A/NN2 counters (which already bound it).

## Open questions
- RTARG recycle behaviour (see Deviations): is the stale push-list pop a
  real flight behaviour worth reproducing? Kept the sane value.
- The precision phase runs entirely inside one job between INTSTALL sleeps;
  a real AGC would also be preempted by higher-priority jobs. Fine for the
  simulator's cooperative executive.
- RESOLVED (review-guid-entry): the RTARG pop was traced in the rope
  (probe): on a V32 recycle the AGC pops six words from below the VAC
  area, i.e. garbage; the C keeps the vector saved by the targeting step
  (DEVIATION, comment in program.c). The cooperative executive question
  needs no code change.

## Lessons
- Comment terminators: AGC vector names end in `/` (R(T1)/, UR1/, V2(T1)/)
  and multiply is `*` in the listings, so "UR1/*X" inside a C comment opens
  a nested comment (-Wcomment, an error under -Werror) and "X*/" closes one
  early. Write "UR1/ x X" or put a space between `/` and `*`.
- POLY coefficients: the 2DEC "B-3/B-1/B1" annotations are applied to the
  stored words; feed the raw words (value x 2^scale x 2^28) to agc_dp_poly,
  and "DEC 1" before them means 3 coefficients (degree 2).
- PDDL then DDV with no address: DDV pops the pushed word as the divisor
  (DV/VC in P37T, not VC/DV).
- An interpretive "VLOAD" with no address pops the push-down list; if the
  code can be re-entered (V32 recycle) the popped cell is stale. Save the
  value in module storage instead and record the deviation.
- INTSTALL sleeps: return AGC_STATUS_OK from the job when the integration
  call says BUSY, and pass the job id that must resume (the AGC's return
  address after INTSTALL); keep the iteration state in module erasables.
- Scale pairs B29/B27 (earth/moon) collapse when the program rejects one
  body; say so once in the internal header rather than at every use.
