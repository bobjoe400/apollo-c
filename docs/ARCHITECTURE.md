Layering (lower may not call higher; tools/depgraph.py checks it and the
upward-call table in docs/overview/README.md is empty):
core < exec < io/imu/nav (with the digital autopilots csm/dap, lm/dap) <
guidance = programs < csm|lm < sim, erasable_map.

Dispatch: `src/exec/dispatch.c` holds the one `switch` from `agc_job_id_t`
/ `agc_task_id_t` to the job/task functions, so the call graph stays
static and recursion-free (rules 1 and 9). It and `include/agc/exec/jobs.h`
are generated from `tools/registry.tsv` (one row per id: CSM and LM
handler, owning folder, AGC label); to add a job or task, add a row and run
`python3 -I tools/gen_registry.py && make format`. The file is four flat
`switch`es (CSM jobs, CSM tasks, LM jobs, LM tasks), one `case` per
registry row in table order, plus the two entry points that pick the
vehicle; it carries the rule 4 exemption marker (CODING_STANDARD.md).

Layering exceptions (documented, the only places a lower layer calls up):
src/exec/dispatch.c (jobs and tasks), src/exec/interrupts.c
(agc_dispatch_rupt), src/exec/nouns.c (noun data above io, read by id by
pinball and by the downlink's DELVSLV), and src/exec/change_program/ (V37,
fresh-start resets: the AGC keeps these in the restart log section).
src/erasable_map/ (erasable access by AGC address: pinball's
machine-address nouns, V71/V72, the downlink erasable dump, the LM
systems test, NASSP) sits on top because it maps every owner's storage;
calls into it from below are the address column, not upward calls.
Shared code that goes on in a vehicle's job body (P52's star selection,
recheck and landing site steps, V46's DAPFIG, V82CALL, R30's CANDEL)
jumps by job id through agc_exec_jump; one registry row names the CSM and
the LM body. Header includes of a higher subsystem for types and ids only
are listed in the overview ("Header dependencies") and are not calls.

File-name rule: inside a folder a file drops any prefix that only repeats an
enclosing folder name (conic/kepler.c, not conic/conic_kepler.c); AGC names
and _csm/_lm suffixes in shared folders are kept.

Subfolder rule: a src/ subfolder exists only when it holds >= 3 files;
otherwise its files stay in the parent. A private header included from a
different folder is promoted to include/agc/ with an `agc_` prefix, so no
moved file needs a `../` include (the one pre-existing cross-folder include,
csm/prelaunch_align.c -> ../imu/imu_pending.h, is untouched).

## Folder rules (2026-10-10)

* A file's folder path says where it belongs; its name says what it does.
  No folder-name prefixes on files, no `agc_` prefix on .c files.
* Three or more files sharing a prefix in one folder form a subfolder
  named by the prefix (burns/sps/, dsky/pinball/, dsky/nouns/, core/interp/).
* Shared glue stays at the parent level; never a `common/` folder.
* A subfolder needs at least three files.
* No adapter layers. Files named glue, shim, ext, pending, adapter or
  wrapper are scaffolding from parallel translation and are deleted at
  integration. A module calls another only through that module's public
  header, with the real function names. (mysubs.c is NOT such a file: MYSUBS
  is a real AGC log section.)

## Header layout (2026-10-10)

```
include/agc/
  core/       status.h assert.h word.h interp.h constants.h state.h channels.h
              flags_common.h flags_csm.h flags_lm.h
  exec/       exec.h jobs.h (generated)
  io/         dsky.h nouns.h service.h
  imu/        imu.h
  nav/        conic.h integration.h auxiliary.h
  guidance/   guidance.h
  programs/   rendezvous.h alignment.h
  csm/        entry.h entry_lexicon.h dap.h
  lm/         landing.h dap.h
```

* Include as a path: `#include "agc/nav/conic.h"`. The `agc/` directory is
  the namespace; file names carry no prefix.
* Public headers mirror the src/ subsystem tree.
* A header used by one lane only lives beside its code as `internal.h` /
  `pending.h` at the lane's parent folder (src/csm/dap/internal.h) and is
  included relatively (`"../internal.h"`).
* No `*_pending.h`, `*_internal.h`, ext, glue or shim files exist (folded
  into the real API headers at integration, 2026-10-10).
