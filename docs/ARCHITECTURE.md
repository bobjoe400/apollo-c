### src/nassp versus sim/nassp

`src/nassp/` holds only what NASSP's own build compiles into
Saturn5.dll and LEM.dll: the engine shim and the CMake project that
NASSP's top CMakeLists takes in through
`sim/nassp/patches/0001-apollo-c-agc-backend.patch`. It is C under the
same rules as src/, but host-only: the Makefile's LIB_SRCS and the module map
skip it, and it is built on the Windows host with MSVC. `sim/nassp/` is
everything that drives or judges a run: the offline replay harness
(`replay.c` links the shim on Linux against libagc and, separately,
NASSP's own yaAGC), the mission tables, the Lua milestone scripts, the
host scripts and the scenario images.

### The address map at the top

The C keeps every erasable in its owner's typed storage (rule 6), not in
an addressable array. Whatever sees the AGC as an addressable memory --
pinball's machine-address nouns, V71/V72, the downlists and the erasable
dump, the LM systems test, NASSP's scenario load and save -- goes through
`src/erasable_map/address_map.c` (`agc_erase_read_ecadr`,
`agc_erase_write_ecadr`). Because it reaches the storage of every
subsystem, it sits above all of them; calls into it from below are the
address column (the C form of an ECADR operand), not upward calls, and
`tools/depgraph.py` counts them that way (ADDRESS_COLUMN). Core keeps only
the raw word image and the map's shadow words (`src/core/ecadr.c`).

### internal.h

A folder's private declarations (the prototypes its files share, its
constants, its state structs) are in that folder's `internal.h`, included
as `"internal.h"` by its files and as `"../internal.h"` by its subfolders'
files. Nothing outside the folder includes it, with three recorded
exceptions: src/lm/radar and src/lm/navigation include
`src/programs/navigation/internal.h` (the P20-P25 vehicle side of the
shared rendezvous core), and src/nassp/engine.c includes
`src/sim/internal.h` (the host hooks it defines). A declaration another
folder needs goes into the subsystem's public header in include/agc/.

Layering (lower may not call higher; tools/depgraph.py checks it and the
upward-call table in docs/overview/README.md is empty):
core < exec < io/imu/nav (with the digital autopilots csm/dap, lm/dap) <
guidance = programs < csm|lm < sim, erasable_map.

Dispatch: `src/exec/dispatch.c` holds the one `switch` from `agc_job_id_t`
/ `agc_task_id_t` to the job/task functions, so the call graph stays
static and recursion-free (rules 1 and 9). It and `include/agc/exec/jobs.h`
are generated from `tools/registry.tsv` (one row per id: CSM and LM
handler, owning folder, AGC label); to add a job or task, add a row and run
`python3 -I tools/gen_registry.py && make format`. The file is four flat
`switch`es (CSM jobs, CSM tasks, LM jobs, LM tasks), one `case` per
registry row in table order, plus the two entry points that pick the
vehicle; it carries the rule 4 exemption marker (CODING_STANDARD.md).

Layering exceptions (documented, the only places a lower layer calls up):
src/exec/dispatch.c (jobs and tasks), src/exec/interrupts.c
(agc_dispatch_rupt), src/exec/nouns.c (noun data above io, read by id by
pinball), and src/exec/change_program/ (V37,
fresh-start resets: the AGC keeps these in the restart log section).
src/erasable_map/ (erasable access by AGC address: pinball's
machine-address nouns, V71/V72, the downlists and the erasable dump,
the LM systems test, NASSP) sits on top because it maps every owner's storage;
calls into it from below are the address column, not upward calls.
Shared code that goes on in a vehicle's job body (P52's star selection,
recheck and landing site steps, V46's DAPFIG, V82CALL, R30's CANDEL)
jumps by job id through agc_exec_jump; one registry row names the CSM and
the LM body. Header includes of a higher subsystem for types and ids only
are listed in the overview ("Header dependencies") and are not calls.

File-name rule: inside a folder a file drops any prefix that only repeats an
enclosing folder name (conic/kepler.c, not conic/conic_kepler.c); AGC names
and _csm/_lm suffixes in shared folders are kept.

Subfolder rule: a src/ subfolder exists only when it holds >= 3 files;
otherwise its files stay in the parent (src/lm/ascent.c,
ags_initialization.c, rendezvous_final_attitude.c). A private header
used across folders is promoted to include/agc/ (internal.h above).

## Folder rules (2026-10-10)

* A file's folder path says where it belongs; its name says what it does.
  No folder-name prefixes on files, no `agc_` prefix on .c files.
* Three or more files sharing a prefix in one folder form a subfolder
  named by the prefix (burns/sps/, dsky/pinball/, dsky/nouns/, core/interp/).
* Shared glue stays at the parent level; never a `common/` folder.
* A subfolder needs at least three files.
* No adapter layers. Files named glue, shim, ext, pending, adapter or
  wrapper are scaffolding from parallel translation and are deleted at
  integration. A module calls another only through that module's public
  header, with the real function names. (mysubs.c is NOT such a file: MYSUBS
  is a real AGC log section.)

## Header layout (2026-10-10)

```
include/agc/
  core/          status.h assertion.h word.h interp.h interp_words.h
                 constants.h state.h channels.h flags_common.h
                 flags_csm.h flags_lm.h
  exec/          exec.h jobs.h (generated)
  io/            dsky.h nouns.h service.h
  imu/           imu.h
  nav/           conic.h integration.h auxiliary.h
  guidance/      guidance.h
  programs/      rendezvous.h alignment.h
  csm/           entry.h entry_lexicon.h dap.h
  lm/            landing.h dap.h
  erasable_map/  address_map.h
```

* Include as a path: `#include "agc/nav/conic.h"`. The `agc/` directory is
  the namespace; file names carry no prefix.
* Public headers mirror the src/ subsystem tree.
* A header used by one folder only lives beside its code as `internal.h`
  (see internal.h above); two private headers have their own names,
  src/core/mpac.h and src/lm/radar/radar.h.
* No `*_pending.h`, `*_internal.h`, ext, glue or adapter files exist
  (folded into the real API headers at integration, 2026-10-10). The one
  file called a shim, src/nassp/engine.c, is not an adapter layer inside
  the program: it is the host interface NASSP links in place of yaAGC.

## Known limitations

* **Zero-time executive.** A C job runs whole in no AGC time; interrupts
  are taken between jobs and between scaler counts (src/sim/clock.c
  NOTES). Two ordering deviations stand in for execution time where the
  order of events depended on it: the landing radar reads wait while
  another job holds the radar
  (`src/lm/burns/servicer/landing_radar.c:agc_job_lrvjob`, flight bug 6),
  and a job that reschedules itself with CHANG1 runs at most once a
  centisecond (`src/exec/executive.c:agc_exec_run_one`). Behaviours that
  exist only because of execution time (1201/1202 overloads, 01703 slip
  size, how long a computation takes before a deadline, R22's mark pace)
  are expected deviations, listed with their traces in
  docs/modules/nassp-integration.md ("Expected deviations (timing)") and
  not modelled (history/PLAN.md, "Principle: functional fidelity, not timing
  emulation"). yaAGC remains the tool for timing-exact runs.
* **Scenario restore.** NASSP saves the running AGC (registers, core sets,
  VAC areas, waitlist); the C has no addresses for those, so a load
  restarts the computer (GOJAM -> GOPROG) with the erasable kept through
  the address map, where NASSP's yaAGC resumes the image. A type C
  restart phase whose PHSNAMEn is a rope address cannot be resumed (the C
  keeps job ids; `agc_restart_group` ends BAD_ARG for that group): after
  a PDI load P63's display is not re-shown. The restart also re-zeroes
  the LM DAP's hold attitude to the present CDUs and drops the CMC's
  optics drive. An erasable the map does not carry is lost at a load
  (flight bugs 1, 5, 12-14 were such gaps).
* **DOWNLIST_SKIP** (sim/nassp/replay.py, docs/modules/telemetry.md): the
  downlist words the C cannot reproduce: RSBBQ (no BBANK or Q register),
  CADRFLSH / CADRMARK / TEMPFLSH (no rope addresses), ARUPT (no A
  register), the high words of DPs the AGC left with disagreeing signs
  (THETADX..Z, LEMMASS: the C keeps the value), and on the loaded LM
  images the words of the re-shown display, RADMODES bit 6 and TTOGO.
* **Stubs**: V27 DSPFMEM (fixed memory is not modelled) and the CM
  prelaunch IMU performance-test drift branches that end in the
  erasable-memory program LAT(SPL), which is not in the rope
  (history/MODULE_STATUS.md).
